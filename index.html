What it is

Open Intelligence is an open-source library and a coordination network. Anyone with an invite installs the library, connects a node, and contributes their own compute — and, in later phases, their own language model — to shared research problems.

A central coordinator keeps the ledger: which problems exist, which work is leased to whom, and which results have been accepted. It never ships runnable code to a node. Tasks, artifacts and contracts are data; a node runs only the handlers it installed, and only a deterministically checked, Ed25519-signed result leaves the machine.

The goal is not more raw compute. Distributed computing is largely a solved problem. The open question is epistemic: how a network of untrusted, heterogeneous participants can produce results that are checked, attributable and worth building on.

Why distributed research

Large agent swarms already work when a single organisation owns every machine, every model and every result. What has not been shown is the same loop running on independently owned, untrusted nodes, with problems chosen in the open and results that anyone can re-check.

Structured collective intelligence — decomposition, exploration, cross-pollination, adversarial verification, adaptive allocation — produces more verified progress per token than the same budget spent on independent agents. Working thesis, Open Intelligence vision draft

That thesis is a bet, not a result. The network exists to test it under honest conditions: one task, a fixed budget, and a comparison between one strong agent, many independent agents, and many agents coordinated by the network. A null result is a real possibility, and one we commit to publishing.

Distribution changes the trust model rather than the arithmetic. Volunteers keep their own keys and credentials, the coordinator never sees how a result was produced, and correctness comes from verification and replication — never from who submitted it, and never from a vote.

How it works

  1. Run a nodeInstall the library on your own machine. It creates an Ed25519 identity that never leaves your disk.
  2. ConnectRedeem an invite and receive a coordinator-signed contract, verified against a shipped trust root. The node only ever dials out over HTTPS; nothing listens on your machine.
  3. LeaseThe node leases a unit of work. Leases are renewed by heartbeats and expire on silence, so work from a vanished node is reassigned automatically.
  4. Solve locallyA shipped handler, or in later phases the node’s own LLM inside a per-attempt local sandbox, works the task. No code arrives over the network.
  5. Check deterministicallyThe node checks its own answer with the problem’s objective verifier before submitting anything.
  6. Sign the resultOnly the checked result, signed with the node’s key, crosses the wire. Sandbox code, logs and state stay local.
  7. Coordinator verificationThe coordinator checks the signature and the lease, re-verifies the result, and records it. Duplicate results are legal and serve as replication.
  8. Knowledge and leaderboardAccepted results become part of the shared record, with provenance, and the best verified scores are published.

Join

  1. Install the library (Python 3.9 or newer).

    pip install open-intelligence

  2. Connect with your invite. The trust root is the coordinator’s public key.

    open-intelligence connect \
  --endpoint   https://api.open-intelligence.space \
  --trust-root <coordinator-pubkey> \
  --invite     <your-invite-token>

  3. Start contributing. Runs in the foreground; Ctrl-C stops and drains.

    open-intelligence start

Phase A is invite-only, and the package is installed from the repository until its first public release. Check your node any time with open-intelligence status.
